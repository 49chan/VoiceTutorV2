## 🛠️ 주요 개발 및 조치 내역 (세부 사안)

### 1. 보안 및 인증 아키텍처 고도화
* **구글 이메일 로그인 차단벽 도입**:
  * 초기 화면 진입 시 **시작하기** 버튼을 잠그고, 비로그인 상태 진입 시 로그인 화면으로 유도하는 보안 락킹 로직을 구현했습니다.
  * 동적으로 승인할 로그인 이메일 정보(기본값: `yqhah@gmail.com`)를 설정창에서 암호화 저장할 수 있도록 기능을 탑재했습니다.
* **비인가 이메일 접근 시 API Key 자동 즉시 파기 (Wipe)**:
  * 백엔드 API 서버(`api/login`)에서 입력된 이메일이 설정 파일에 기록된 이메일과 다를 경우, 위협 행위로 판단하여 디스크에 저장된 `azure_speech_key`, `google_vision_ocr_key`, `google_sheets_webhook_url` 등 **모든 유료 서비스 인증 토큰을 공백(`""`)으로 밀어버리는 자동 포맷 기능**을 연동했습니다.
* **API Key 화면 복사 방지 (Credential Masking)**:
  * 프론트엔드가 설정을 불러올 때 백엔드 단에서 저장된 비밀 값들을 일괄적으로 `********`로 치환하여 반환하도록 함으로써, 화면이나 개발자 도구의 네트워크 패킷을 통해 비밀키가 유출되는 사고를 차단했습니다.
  * 사용자가 입력을 건드리지 않고 그대로 저장할 경우, `********`로 제출된 값들은 덮어쓰지 않고 디스크의 원래 암호화 값을 보존하는 바이패스 로직을 백엔드에 설계했습니다.

### 2. UI / UX 및 뷰포트 반응형 개선 (모바일 & 태블릿)
* **100dvh (Dynamic Viewport Height) 전수 도입**:
  * 모바일 크롬, 사파리 등의 브라우저에서 주소창이나 상하단 툴바가 접히고 펼쳐질 때 화면이 깨지거나 버튼이 밀리는 현상을 막기 위해, 전체 레이아웃 높이 계산 단위에 `100dvh`를 대입하여 유동적인 맞춤 뷰포트를 완성했습니다.
* **모바일 하단 Safe Area 및 스크롤 여백 보정**:
  * 아이폰 및 갤럭시 최신 기기들의 하단 홈바(Safe Area) 영역과 로그인/설정 서랍창의 버튼들이 겹치지 않도록 `env(safe-area-inset-bottom)` 높이 오프셋을 자동 계산하여 여백을 부여했습니다.
  * 긴 설정창을 스크롤할 때 맨 하단 버튼이 묻히지 않도록 `.drawer-body` 하단에 `30px`의 안전 스크롤 패딩을 주입했습니다.
* **화면 높이별 자동 축소 반응형 미디어 쿼리**:
  * 화면 높이가 `720px` 이하인 작은 모바일 장치에서는 첫 화면의 서비스 도식화 이미지 최대 크기를 `320px`에서 `220px`로 자동 축소하고 슬로건 폰트 크기를 줄이도록 하여, **첫 화면의 "시작하기" 버튼이 잘림 없이 완벽히 화면 중앙에 들어오도록 개선**했습니다.

### 3. 파일 처리 방식 및 파일명 디스플레이 오차 해결
* **텍스트 파일(.txt) 임포트 시 즉시 렌더링**:
  * 사용자가 교재 텍스트 파일을 열었을 때, 기존의 편집 모드 상태에 영향을 받지 않고 **즉시 뷰어 화면에 줄바꿈이 적용된 상태로 바로 노출**되도록 `forceViewMode()` 라이프사이클을 삽입하여 사용성을 개선했습니다.
* **JSON 이력 복원 시 파일명 매핑 오류 수정**:
  * `.json` 평가 이력 파일을 업로드했을 때, 상단에 원본 텍스트 파일명(`.txt`)이 계속 출력되던 오류를 가공하여 사용자가 로드한 **실제 이력 JSON 파일명(예: `EBSj_250102_01.json`)이 출력**되도록 덮어쓰기 처리를 진행했습니다.
* **JSON 이력 검토 모드 시 낭독 기능 버튼 비활성화**:
  * 평가가 이미 종료된 `.json` 이력 파일 상태일 때는 읽기 전용 상태가 되므로 상단 액션 바의 `변환`, `녹음`, `중지`, `평가` 버튼들을 모두 비활성화(`disabled` 및 흐리게 표시) 상태로 잠궈 오작동을 차단했습니다. `.txt` 또는 PDF 페이지 추출 시에만 다시 원상태로 켜집니다.

### 4. 네트워크 접속 편의성 및 디버깅 강화
* **백엔드 외부 IP 접속 바인딩 (`0.0.0.0`)**:
  * 모바일 기기에서 Wi-Fi를 통해 PC 백엔드 서버에 직접 연결하여 실기 테스트를 진행할 수 있도록, `main.py` 구동 호스트를 `127.0.0.1`에서 모든 인터페이스 오픈 형태인 `0.0.0.0`으로 개정했습니다.
* **프론트엔드 동적 백엔드 API URL 주소 입력기 탑재**:
  * 모바일 기기로 배포된 웹사이트에 접속해 테스트할 때 로컬 PC API 서버를 유연하게 가리킬 수 있도록, 초기 화면 설정창 내부에 `백엔드 서버 URL (API 주소)` 입력란을 생성하여 클라이언트 단의 `localStorage`로 관리되도록 구현했습니다.
* **설정 저장 네트워크 에러 팝업 세부화**:
  * 설정 저장 중 "서버 연결 실패" 발생 시, 사용자가 입력 또는 지정한 실제 백엔드 URL(예: `http://192.168.0.15:8000`)을 경고창 문구에 명시해줌으로써 어떤 포트나 IP가 차단되었는지 직관적으로 에러를 자가 진단할 수 있도록 보강했습니다.

   - 기기 및 환경 설정 드로어 창에 **화면 테마 설정** 옵션을 드롭다운 형식으로 추가했습니다.
   - **블랙 (기본)**과 **화이트** 테마를 제공하며, 변경 시 배경 및 텍스트 색상이 화이트/블랙에 맞게 실시간 전환되도록 CSS 및 JS를 결합 설계했습니다.
   - 사용자가 변경한 테마는 브라우저의 `localStorage`를 통해 영구 보존되도록 구현하여 새로고침 시에도 유지됩니다.

2. **변환 (Remove Convert Button)**
   - 상단 액션 바에서 불필요하게 단독으로 노출되던 [변환] 버튼을 숨겨 화면을 보다 간결하게 리팩토링했습니다. (기능은 파일열기에서 PDF 파일 업로드 시 자동 실행되는 방식으로 정상 유지)

3. **녹음 (Record Button & Timer)**
   - 음성 평가 완료 후 결과 데이터가 표시되면 잘못된 중복 조작을 막고자 [녹음] 버튼을 비활성화 처리했습니다.
   - 녹음 도중 우측 하단에 표시되던 2분 제한 타이머를 우측 상단 플레이 상태 아이콘 바로 왼쪽으로 위치 이동하여 사용자 시선 집중도를 높였습니다.

4. **평가 (Evaluate Button & Layout)**
   - 평가가 완료되면 [평가] 버튼 역시 비활성화 상태로 잠그도록 제어 로직을 구현했습니다.
   - 기존에 화면 하단에 자리하여 가시성이 떨어졌던 종합 피드백 리포트와 전체 점수판 영역을 낭독 카드 바로 위인 **화면 최상단**에 고정 노출하여 스크롤 없이 실시간 점수 확인이 가능하도록 레이아웃을 전면 배치 수정했습니다.
   - 만약 낭독 문장을 임의 수정하여 [저장]하거나 편집 모드를 탈출하는 경우, 기존 평가 리포트가 초기화(`resetEvaluationDisplay`)되면서 새로운 녹음/평가를 할 수 있게 버튼 상태를 자동으로 잠금 해제하는 선순환 리셋 주기를 완성했습니다.

5. **JSON 파일 로드 시 추가 개선 및 스크롤 최적화**
   - JSON 이력 복원 시 사용자의 텍스트 수동 편집 오류 방지를 위해 연필 버튼(편집 기능)을 비활성화하고, 일반 TXT 파일이나 PDF를 로드할 때만 다시 연필 버튼이 활성화되도록 예외 처리를 진행했습니다.
   - 연습 텍스트나 결과의 줄 수가 길어져 화면 바깥으로 요소들이 밀리는 현상을 해결하기 위해, 플렉스 박스의 내부 크기 제한 속성(`min-height: 0`)을 적용하여 텍스트 영역 내에서만 안전하게 스크롤이 되도록 레이아웃 높이 연산을 수정했습니다. 이로 인해 화면 해상도가 낮거나 긴 문장의 이력을 열어도 하단의 설정 및 종료 버튼이 가려지지 않고 깔끔하게 유지됩니다.
   - 화이트 테마(라이트 모드) 배경에서 투명하게 겹쳐 잘 보이지 않던 점수판 그라데이션의 시작 투명도를 테마별 CSS 변수(`--score-gradient-start`)로 바인딩하여, 라이트 모드에서도 점수가 어두운 그라데이션으로 선명하고 직관적으로 보이게 수정 완료했습니다.

6. **PDF 추출 후 편집 자동 저장 및 구글 드라이브 연동 예외 조치**
   - **편집본 자동 저장 구현**: 기존에는 수동 텍스트 편집 후 반드시 플로피 디스크(저장) 아이콘을 직접 눌러야만 서버에 전송되었으나, 사용자가 편집 모드를 완료(체크 버튼 클릭으로 뷰어 복귀)할 때 자동으로 텍스트 저장(`saveEditedText()`)이 실행되도록 UX 흐름을 자동화했습니다.
   - **구글 드라이브 업로드 경로 예외 조치**: 서버 디렉토리 구조가 `api/` 내부로 통합 및 변경되면서 발생한 `ImportError`로 인해 구글 드라이브 파일 업로드 함수가 백그라운드 상에서 실패하던 현상을 발견했습니다. 백엔드 진입점인 `api/index.py` 내의 `upload_file_to_drive` 모듈 로드 경로를 다중 구조(`api.google_drive` 및 `google_drive`)로 보완하여 로컬 개발 환경과 서버리스 환경 모두에서 구글 드라이브에 정상적으로 저장되도록 예외를 조치했습니다.
